# ایمنی — تغییر روی سایت زنده

قبل از هر پیشنهاد اجرایی این فایل را بخوان.

## کارهایی که ریسک بالا دارند

- کوئری روی دیتابیس (به‌خصوص UPDATE، DELETE، REPLACE)
- اسکریپت یا WP-CLI روی سایت
- تغییر redirectها، `robots.txt`، canonical، noindex، permalink یا sitemap
- ویرایش گروهی محتوا، title/meta، لینک‌ها یا دسته‌بندی‌ها
- فعال/غیرفعال کردن یا به‌روزرسانی افزونه‌ها
- حذف یا ادغام صفحات

## روال اجباری برای هر پیشنهاد اجرایی

1. **توضیح تغییر:** دقیقاً چه چیزی، روی چه صفحاتی، و چرا.
2. **ریسک:** بدترین حالت چیست (مثلاً افت ایندکس، لینک شکسته، از دست رفتن محتوا).
3. **بکاپ:** بکاپ کامل فایل‌ها و دیتابیس را صریح بخواه و تا تأیید من ادامه نده.
4. **staging:** اجرا را اول روی نسخه‌ی staging پیشنهاد بده و بعد از تأیید روی سایت زنده.
5. **راه برگشت:** برای هر تغییر یک مسیر rollback مشخص بنویس.
6. **تأیید پس از اجرا:** چه چیزی را چک کنم تا مطمئن شوم درست انجام شده (URL نمونه، Search Console، sitemap).

## قوانین کلی

- به دیتابیس یا سایت زنده مستقیم وصل نشو و رمز، کلید API یا دسترسی نخواه. فقط روی داده‌ی export کار کن.
- کوئری و اسکریپت را قابل بازبینی بنویس: اول SELECT برای دیدن تأثیر، بعد تغییر.
- تغییرهای بزرگ را به مرحله‌های کوچک بشکن؛ یک دسته‌ی کوچک، بررسی، بعد ادامه.
- اگر مطمئن نیستی، اجرا را پیشنهاد نکن و سؤال بپرس.
